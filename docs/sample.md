# 示例文档 · 关于本项目

> 这是一份**示例知识库**，用来演示 RAG 检索问答的效果，同时替代缺失的知识来源。
> 想用自己的文档，把 `.md` 或 `.txt` 放进这个 `docs/` 目录即可（`docs/` 已在 `.gitignore` 里，不会被上传）。

## 这个项目是做什么的

把一份长文档做成可以「用自然语言提问」的知识库，答案全部来自原文，并且会标出引用了哪几段资料。

和直接用大模型聊天的区别在于：大模型会编造内容，而这个项目在提示词里做了约束 ——
如果资料里找不到答案，它必须回答「资料中没有相关内容」，而不是靠记忆瞎猜。

## 三步流程是怎么走的

- **第一步：建索引**（`step1_build_index.py`）
  把文档按标题切成小块，每块长度控制在 600 字以内，再算成向量存起来。
- **第二步：命令行问答**（`step2_ask.py`）
  把问题也算成向量，和所有块比相似度，取最像的几块喂给大模型生成答案。
- **第三步：网页界面**（`step3_app.py`）
  用 Streamlit 做成聊天式的界面，可以调「检索块数 Top-K」，也能展开看检索到的原文。

## 为什么用 TF-IDF + SVD 算向量，而不是 BGE 这类预训练模型

预训练向量模型（例如 `bge-m3`）语义效果更好，但有两个现实成本：模型体积大（1 GB 以上）、
在受限网络下下载困难。TF-IDF 加 SVD 降维属于经典的潜在语义分析（LSA）路线，
不需要任何模型文件，纯本地计算，建一份索引只要几秒，对「单份文档、几千个块」这个规模完全够用。

代价是**语义泛化能力有限**：换个说法提问、文档里没有字面相同的词时，检索效果会下降。
如果要换成预训练向量，只需要改「算向量」那一处，检索和生成逻辑都不用动。

## 什么情况下回答「资料中没有相关内容」

判断权交给大模型，而不是设置一个相似度阈值。这样做的好处是简单直接，
坏处是**小模型在「该不该拒答」这个判断上不稳定** —— 有时资料明明有相关内容，它也会保守地拒答。

实测下来，提示词的措辞会直接影响这个行为：
写成「资料里没有的必须拒答」，模型会变得过度保守，几乎什么都拒；
改成「只要资料和问题沾边，就要基于资料回答」，拒答准确率明显提高。

## 切分策略里最容易踩的坑

最初只把 1~3 级标题当作标题，结果文档里用 4 级标题写的问答（答案藏在折叠块中）
被切成了「只有问题、没有答案」的碎块 —— 检索相似度很高，但答案根本不在里面。

修法是三条：把 4 级标题也算作标题；标题强制并入下面正文，不让它单独成块；
每一块在向量化之前，前缀加上「章节路径 + 标题」，让向量带上位置信息。
改完之后块数从 2042 降到 1260，每块更完整，问答正确率明显上升。

## 运行环境要求

- Python 3.10 以上
- 本地已安装 Ollama，并且已经拉取对话模型（本项目用 `qwen2.5-3b`）
- 依赖见 `requirements.txt`

Ollama 默认监听 `127.0.0.1:11434`。如果连不上，说明服务没启动 ——
Windows 上从开始菜单打开 Ollama 即可，其他系统执行 `ollama serve`。
