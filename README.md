# 文档问答助手（RAG）

把自己的长文档做成一个能**用自然语言提问**的知识库。答案全部来自原文，并标注引用了哪几段资料；
资料里没有的内容，它会直接回答「资料中没有相关内容」，而不是编一个出来。

完全本地运行：向量自己算，生成模型跑在本机 Ollama 上，**不调用任何云端 API、不需要 API Key**。

---

## 效果

用一份 50 万字的学习笔记做知识库（切成 1260 块），实测（模型已加载，CPU 推理）：

| 提问 | 回答 | 耗时 |
|---|---|---|
| 装饰器的原理是什么？ | 答出「接收函数并返回函数的可调用对象」，并说明带参装饰器为什么要三层 | 1.4 s |
| MySQL 为什么用 B+ 树做索引？ | 答出「非叶子节点只存键、扇出大」「数据都在叶子节点、双向链表让范围查询快」「磁盘 IO 次数稳定」 | 2.3 s |
| 明天天气怎么样？ | **资料中没有相关内容** | 0.1 s |

最后一行是这个项目的重点：**它敢承认自己不知道。** 大模型最大的问题是会一本正经地胡说八道，
RAG 的价值就是给它的嘴装一道闸门。

## 它是怎么工作的

```
文档 (.md / .txt)
   │  按 1~4 级标题切块，每块 ≤ 600 字，块前缀带上「章节路径 + 标题」
   ▼
切分后的块（1260 块）
   │  TF-IDF（字符 1-2 gram）→ TruncatedSVD 降到 256 维 → L2 归一化
   ▼
向量索引（vectors.npy / tfidf.joblib / svd.joblib / chunks.json）

提问 ─ 同样算成 256 维向量 ─ 与全部块做余弦相似度 ─ 取 Top-K 块
                                                        │
                              拼进提示词（要求「只依据资料回答」）▼
                                          本地 Ollama + Qwen2.5-3B 生成
                                                        │
                                                     带出处的回答
```

## 快速开始

**0. 准备模型**（只用一次）

```bash
ollama pull qwen2.5-3b
```

没装 Ollama 的话先去官网装一个。服务没启动时，脚本会检测到并提示怎么启动。

**1. 装依赖**

```bash
pip install -r requirements.txt
```

**2. 放你要问答的文档**

脚本按这个顺序找文档，**越靠前优先级越高**：

| 顺序 | 来源 | 适合什么场景 |
|---|---|---|
| ① | 命令行参数 `python step1_build_index.py 你的文档.md` | 临时换一份文档试试 |
| ② | 项目根目录的 `local_source.txt` | **在本机固定一份文档**（日常用最省事） |
| ③ | `docs/` 目录里唯一的 `.md` / `.txt` | 默认；仓库自带 `docs/sample.md` 可以先用 |

**选一种就行，下面是三种分别怎么用。**

**方式 ③ · 最省事**

把 `.md` / `.txt` 直接丢进 `docs/` 目录，然后跑 step1 即可。仓库自带的 `docs/sample.md`
可以先拿来试用。`docs/` 已经写进 `.gitignore`，**你放进去的私人文档不会被提交**。

**方式 ② · 本机固定一份（推荐日常用）**

如果你的文档放在项目外面（比如自己的笔记目录），又不想每次都敲一遍长路径：

1. 把 `local_source.txt.example` 复制一份，去掉 `.example` 后缀，变成 `local_source.txt`
2. 打开它，把最下面那一行改成你文档的**绝对路径**
3. 之后 `python step1_build_index.py` 不带参数就会读它

`local_source.txt` 已经写进 `.gitignore`，**不会上传**，所以可以放心写本机路径。

> 这也是「本机私有配置不进仓库」的常见做法：**代码里只留回退逻辑，
> 路径、凭据这类只属于本机的东西放进被 gitignore 的本地文件**。
> 效果就是 —— 你本机读自己的文档，别人 clone 下来直接读 `docs/sample.md`，两边互不干扰。

**方式 ① · 临时用**

不改任何文件，直接把路径当参数传进去：

```bash
python step1_build_index.py path/to/你的笔记.md
```

**3. 建索引**

```bash
python step1_build_index.py
```

**4. 命令行问答**

```bash
python step2_ask.py
```

**5. 网页界面**（可选）

```bash
streamlit run step3_app.py
```

## 几个设计取舍

### 为什么向量用 TF-IDF + SVD，而不是 bge 这类预训练模型

预训练向量模型语义效果更好，但体积大（1 GB 以上）、下载有门槛。
TF-IDF 加 SVD 降维是经典的潜在语义分析（LSA）路线，**零模型文件、纯本地计算、建索引只要几秒**，
对「单份文档、几千个块」这个规模完全够用。

代价是**语义泛化有限**：换个说法提问、文档里没有字面相近的词时效果会下降。
要换成预训练向量，只需要改「算向量」这一处，检索和生成逻辑都不用动 —— 这是当初把三步拆开写的原因。

### 为什么不用 LangChain

整个链路就六步：切分 → 向量化 → 检索 → 拼提示词 → 生成 → 带出处返回。
核心链路手写不到 200 行，每一行都能说清在干什么。引入框架会把这一步变成黑盒，
而调试 RAG 恰恰最需要看清中间每一步（比如「检索命中了但答案不在块里」这种问题）。

### 提示词里「拒答」的措辞边界

判断「资料里到底有没有答案」这件事，交给大模型而不是设相似度阈值。
但实测发现措辞会直接改变行为：

- 写「资料里没有的**必须**回答『资料中没有相关内容』」→ 模型变得**过度保守**，明明有相关资料的题也拒答
- 改成「**只要资料和问题沾边，就要基于资料给出回答**，避免轻易说没有」→ 拒答准确率明显提升

## 踩过的坑

**1. 检索指标好看，不等于链路可用。**
第一版切分后，问「装饰器的原理」，检索返回相似度 0.817 的高分块，点开只有一行：
`#### Q22｜装饰器的原理是什么？` —— 分数很高，但**答案根本不在里面**。
根因是答案写在 4 级标题下面的折叠块里，而切分器只把 1~3 级当标题，标题被切成了独立小块。
修完块数 2042 → 1260，问答正确率大幅上升。
教训：RAG 必须端到端验证，只盯着检索分数会漏掉这类问题。

**2. 块要带上位置信息。**
只在正文上算向量时，「这个报错怎么解决」这类问题会检索得很散。
把「章节路径 + 标题」拼到向量文本前面之后，定位准确了很多。

**3. 本地服务调用要显式绕过系统代理。**
`requests` 默认读 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量。装了代理软件的环境里，
连 `127.0.0.1` 的请求也会被送去代理，报 `ProxyError` 或连接被拒。
代码里显式传 `proxies={"http": None, "https": None}` 解决。

## 已知局限

- **纯本地 CPU 推理**，3B 模型在 CPU 上大约 2~8 秒出答案，首次调用还要加载模型
- **小模型指令遵循不稳定**：3B 模型对**问法**比较敏感，偶尔会对有资料的题目保守拒答。
  实测同一个问题，问「RAG 的完整链路是什么？」能正常回答；
  问成「那 RAG 的完整链路是什么？」（前面多一个「那」）它就回答「资料中没有相关内容」——
  而那一次检索相似度反而是最高的（0.804）。**遇到拒答先换个问法再试，不一定是检索出了问题。**
- **只支持 Markdown / 纯文本**，PDF、Word 需要先转成文本
- **没有会话记忆**，每次提问都是独立的
- 检索是**单次 Top-K**，没有做重排（rerank）

## 可以继续做的方向

- 把向量换成预训练模型（`bge-small-zh` 这类），改进语义泛化
- 加一层 rerank：先召回 20 块，再用交叉编码器精排出 Top-3
- 支持 PDF / docx 解析，直接丢文件进去
- 引用高亮：答案里标出「资料3」时，点击能跳到原文对应位置
